# CHINT 立项内容整理（chint-pm-rat · 产品经理范围）

## Overview

把用户材料整理成**合格的 RAT 立项内容**：按立项表格的栏目组织，只填产品经理范围，每个结论有数字、有口径、有来源。

本技能**不管排版**。不生成 pptx、不套模板、不做字体/分区/字符预算控制。用户要成稿时，由下游（人类排版、`chint-pptx` 等）消费这份内容。

**PM 范围（本技能只整理这些）**：需求背景、产品定义（外观/材质/认证/性能及质量可靠性）、应用场景及客户痛点、竞争对手、目标行业、销售通路、需求来源/规划方向/产品平台、项目计划、承接单位与团队。

**非 PM 区（只留标题，不写内容）**：技术可行性、生产可行性、价格目标成本及毛利、财务可行性——明确标注"留白交其他部门"，不代填、不推测。

## 文件

| 文件 | 用途 |
|---|---|
| `references/content-methodology.md` | 六条内容红线 + 领导常问六问自检（**先读这个**） |
| `references/industry-enum.md` | 目标行业口径枚举（10 项，唯一合法取值） |
| `archive/` | 已退役的 PPT 模板填充链路（模板、生成脚本、校验器、渲染检查、示例 spec、分区规格）。仅作历史参考，**不要使用** |

## 输出结构

按下列栏目输出 Markdown，顺序固定、栏目不增不减；无内容的栏目标注 `待XX确认`，不省略。

```markdown
## 标题
- 类别：改良改进 | 全新开发 | 定制开发
- 产品：<一句话产品名>
- 承接单位：<…或 待确认>
- 项目团队：负责人/产品/研发/制造/质量/财务/供应链

## 标签牌
- 需求来源：<…>
- 规划方向：<…>
- 产品平台：昆仑 | 新锐 | 诺雅克 | （跨品类留空并列入待确认清单）

## 项目计划
P1 项目输入与评估 / P2 选型与认证验证 / P3 供应商与品控准备 / P4 入网与可销售（各给时间或 待排期）

## 需求背景
- 首段：调研时间 + 对象数量 + 规模结论
- 条目：现有产品缺口、通路限定等（每条带数字）

## 应用场景及客户痛点
- 应用场景：1-2 句工况描述
- 客户痛点：每条"要求值 vs 现有值"

## 快览
- 竞争对手：只列最大的【一家】
- 目标行业：行业口径枚举之一（10 项）
- 销售通路：<…>

## 产品定义
- 外观 / 材质 / 认证
- 性能及质量可靠性：逐条回应上面痛点，尺寸给 mm、时间给 ms、成本给 %

## 风险预案（有未落地风险时必填）
| 风险 | 影响 | 应对预案（含量化幅度） | 资源诉求 | 责任人 |

## 有条件立项条件（如需）

## 销售预测交叉验证（有预测时必填）
| 步骤 | 推算过程 | 数据来源 |
结论段：保守/乐观双口径与偏差判断。

## 非 PM 区（留白）
技术可行性 / 生产可行性 / 价格·目标成本·毛利 / 财务可行性 —— 交其他部门续填。

## 待确认清单
逐条列出所有占位字段与决策点。
```

## 工作流

1. **材料定位**：调用带材料路径则直接用；无参 → 扫描 `Projects/` 下最新 RAT/立项相关目录（pptx/xlsx/md 优先），**显式声明假设的目标项目**后再动工，勿默默猜测。
2. **读红线**：`references/content-methodology.md`。
3. **逐栏目整理**：
   - 数字拿不到 → 问一轮；未应答 → 填 `"待XX确认"` 占位继续出草稿，并入待确认清单。**禁止编造数字，禁止删栏目。**
   - **竞争对手**：只列最大的**一家**；一手顺序 = 用户材料 → 无信息则用 `research` skill 联网搜索该细分市占第一，禁止罗列多家。
   - **目标行业**：必须且只能填 `references/industry-enum.md` 的 10 项之一；材料口径映射不清时 AskUserQuestion 确认。
   - 痛点与性能参数**一一对应**（条数 ≤）；痛点每条要"要求值 vs 现有值"。
4. **条件规则**（可观察谓词，逐条判断）：
   - 存在未落地风险 → 风险预案表必填，四要素（风险/影响/预案/资源诉求+责任人）齐全。
   - 有销售预测 → 交叉验证表必填；行业数据拿不到 → 写可推算部分，`数据来源` 标 `"待补充（行业协会/盘厂调研）"`。
   - 技术/生产可行性、价格成本、财务 —— **不写内容**，只留栏目名。
5. **六问自检**：逐条回答领导常问六问；答不上的回改对应栏目。
6. **交付**：输出完整内容 + 待确认清单；用户要成稿时说明交给排版环节，本技能不产出文件。

## 交付前红线速查

| 红线 | 判据 |
|---|---|
| 数字化 | 痛点/收益无数字 → 退回 |
| 痛点↔性能一一对应 | `客户痛点` 条数 ≤ `性能参数` 条数，逐条可对 |
| 交叉验证 | 有预测必须有交叉验证表 + 数据来源 |
| 风险附预案 | 有未落地风险必须有风险预案表，预案含量化措施 |
| 平台命名 | 只允许 昆仑/新锐/诺雅克；跨品类/无平台项目留空并**必须列入待确认清单**（归口由规划定，勿编造） |
| 不越界 | 不在非 PM 区写任何内容 |
