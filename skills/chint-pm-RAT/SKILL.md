# CHINT 立项资料一页纸生成（chint-pm-RAT · 产品经理范围）

## Overview

产出一页纸立项看板 .pptx（16:9，**RAT 表格模版**版式：主 12×9 表格，含正泰 logo）+ 附录A 风险预案 + 附录B 销售预测交叉验证。

**PM 范围（本 skill 只填这些）**：需求背景、产品定义（外观/材质/认证/性能及质量可靠性）、应用场景及客户痛点、竞争对手、目标行业、销售通路、需求来源/规划方向/产品平台标签牌、项目计划、承接单位与团队。
**非 PM 区留白协作**：技术可行性、生产可行性、价格目标成本及毛利、财务可行性——保留标题条，正文留白，其他部门在同一份 RAT 上续填。3 个浮动子表（规格成本/投入/预测）已从基座整体删除。

**核心路线（模板填充）**：`template/one_pager_base.pptx` 是版式唯一正道——RAT 表格模版原样基座 + 模板视觉语言的附录页。
`scripts/fill_one_pager.py` 只做 run/cell 级文字替换与行/列手术，logo/边框/字体构造性继承，格式零漂移。
你负责内容质量：把用户材料转化为合格的内容规格（spec JSON），并用预算预检 + 校验器证明它合格。

## 文件

| 文件 | 用途 |
|---|---|
| `references/spec-schema.md` | spec JSON 每个槽位的定义与示例（**先读这个**） |
| `references/zone-spec.md` | RAT 表格模版实测几何（主 12×9 表单元格地图）/样式常量/字符预算表 |
| `references/content-methodology.md` | 六条内容红线 + 领导常问六问自检 |
| `template/one_pager_base.pptx` | 基座资产：RAT 表格模版原样正文页 + 模板视觉语言附录A/B（勿手改） |
| `scripts/fill_one_pager.py` | spec.json + 基座 → out.pptx（内建字符预算预检，超限拒生成） |
| `scripts/tplkit.py` | 模板手术助手（兼容 WPS hMerge/vMerge 合并模型） |
| `scripts/build_base.py` | 从 RAT 表格模版再生成基座（仅基座需重建时运行） |
| `scripts/validate_one_pager.py` | 校验器（含模板残留检查、字体基线白名单），PASS 才可交付 |
| `scripts/render_check.sh` | 渲染目检一条龙：soffice 探测 + 150dpi + 六敏感区裁切 |
| `references/industry-enum.md` | 目标行业口径枚举（10 项，唯一合法取值） |
| `examples/nxm_spec.json` | 完整合格示例（PM 范围 + 预案 + 交叉验证） |

## 工作流（按序执行，不可跳步）

0. **材料定位**：调用带材料路径参数则直接用；无参 → 扫描 `Projects/` 下最新 RAT/立项相关目录（pptx/xlsx/md 优先），**显式声明假设的目标项目**后再动工，勿默默猜测。
   - **竞争对手**：只列最大的**一家**；一手顺序=用户材料 → 无信息则用 `research` skill 联网搜索该细分市占第一，禁止罗列多家。
   - **目标行业**：必须且只能填行业口径枚举之一（10 项，见 `references/industry-enum.md`）；材料口径映射不清时 AskUserQuestion 确认。
1. **读** `references/spec-schema.md`（含必填槽位清单）。
2. **填 spec**：从用户材料抽取内容逐槽位填写。每个槽位必填：
   - 数字拿不到 → AskUserQuestion 问一轮；**未应答/无值守 → 填 `"待XX确认"` 占位继续出草稿**，交付时把决策点并入待确认清单。**禁止编造数字，禁止删槽位**。
   - 频率检查：痛点每条要有"要求值 vs 现有值"。
   - 长度检查：各区按 `zone-spec.md` 行数/字符预算预写（半角 0.5 折算），超限会在第 4 步被拒。
   - `research` 拆 intro/items；痛点/性能条目**不带编号**（渲染用 Ø/➢ 符号）。
3. **条件规则**（可观察谓词，逐条判断）：
   - `risks` 必填当项目存在未落地风险（四要素：风险/影响/预案/资源诉求 + 责任人）。
   - spec 含销售预测 → `cross_validation` 必填；行业数据拿不到 → steps 写可推算部分，`数据来源` 标 `"待补充（行业协会/盘厂调研）"`。
   - **非 PM 段（技术/生产可行性、价格成本、财务）不写进 spec**——误写会被忽略并提示 SCHEMA v3。
4. **填充**：`python3 scripts/fill_one_pager.py spec.json out.pptx`。脚本先跑字符预算预检：文本框分区超限=裁字风险，拒生成并报出各区现值/限额——按报错压缩 spec 重试，勿绕过；表格/附录超限仅 WARN。
5. **校验**：`python3 scripts/validate_one_pager.py out.pptx --spec spec.json` → 必须 `== PASS`；FAIL 逐条修复后重跑。PASS 后如仍有 WARN，逐条给出处理方式（占位并写入附录A / 待确认清单 / 解释口径），**禁止静默交付带 WARN 的文件**。
6. **目检**：`scripts/render_check.sh out.pptx`（soffice 探测 + 150dpi 整页 + 六敏感区裁切）。目检走**能实际看到像素的通道**——子代理读不了图就主会话自查；判"末字是否被裁"以 150dpi 裁切图为准。LibreOffice 会裁掉超框文字，比 PowerPoint 更早暴露问题。
7. **六问自检**：逐条回答 `content-methodology.md` 的领导常问六问；答不上的回改 spec。
8. **交付**：给可点击文件链接，并列出所有"待确认"占位字段清单。

## 交付前红线速查

| 红线 | 判据 |
|---|---|
| 数字化 | 痛点/收益无数字 → 退回 |
| 痛点↔性能一一对应 | `客户痛点` 条数 ≤ `性能参数` 条数，逐条可对 |
| 交叉验证 | 有预测必须有附录B + 数据来源 |
| 风险附预案 | 有未落地风险必须有附录A，预案含量化措施 |
| 平台命名 | 只允许 昆仑/新锐/诺雅克；跨品类/无平台项目 `产品平台` 填空串，且**必须列入交付待确认清单**（归口由规划定，勿编造） |
| 格式零漂移 | 只经 fill_one_pager 填充；禁止手摆文本框/改基座样式；字体以基座白名单为准 |

## Common Mistakes（来自基线测试的真实失败，勿重蹈）

| 错误 | 正确做法 |
|---|---|
| 无附录页，风险只在正文红字一句带过 | 附录A 四要素表格 + 有条件立项条件清单 |
| 无交叉验证，销售数字直接引用 | 附录B 独立推算链路；推不出时显式标来源待补 |
| 用微软雅黑代替 CHINTinno | 填充脚本继承模板字体，勿手改 |
| 越界填写非 PM 区（技术/生产/价格/财务） | 留白交其他部门；spec 写了会被忽略并提示 SCHEMA v3 |
| 正文超分区字符预算（LibreOffice 渲染直接裁字） | fill_one_pager 已内建预算预检，超限拒生成并报字数；按报错压缩，勿绕过（预算表见 zone-spec.md） |
| 模板残留（模板原文漏覆盖，评审即穿帮） | 校验器有残留检查；spec 必须覆盖全部槽位 |
| 竞争对手罗列多家 / 目标行业自造词 | 竞对只取最大一家（材料优先，缺则 research 联网）；行业必须取枚举值（校验器拦截） |
| 对模板表格做结构手术（WPS hMerge 合并模型，删列错位→渲染炸） | 结构调整只走 tplkit（行级自动识别续格/gridSpan 双模型）；填充一律 table.cell(r,c) 寻址 |

## Red Flags - STOP

- 想跳过校验器"我自己看过了就行" → 不允许，PASS 是交付门槛。
- 想绕过填充脚本手摆文本框"更灵活" → 不允许，版式走 template 基座 + fill_one_pager.py。
- 用户催时间，想砍附录页"先交主体" → 附录是红线，占位也要交。
- 发现 spec 槽位填不出而想删掉 → 占位并上报，不删。
